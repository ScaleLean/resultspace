# Confirmed ResultSpace product contract

ResultSpace is a phone-readable project and company knowledge base. A project states its goal, objectives and current state, links to structured facts and organic knowledge, and has a meaningful chronological log. Issue notes describe upcoming questions or steps; they have no owner, claim or dispatch lifecycle.

The active kinds are project, fact, knowledge, entry (outcome/learning/note), issue_note (displayed as Issues), source, flag and briefing. Company, decision and artifact records remain supporting content. Facts use subject/property/value, text/number/boolean value type, scope/unit, observation date and citations. Knowledge is freeform and may hold sourced method learnings. Existing company-specific kinds are archived read-only during migration rather than interpreted or converted automatically.

`project.context` retrieves explicit links and citations, returning each record with server-attributed revision provenance and sources. Its log is chronological. It returns a truncation indicator; company-wide search provides broader discovery. It does not invent relevance or execute work. Projects may share company facts by linking the same records.

The deterministic Curator checks exact subject/property/scope/unit conflicts, missing sources and stale claims or planning notes. Conflict detection compares typed values without converting units or interpreting prose. Findings retain revision snapshots of all conflicting claims and cited source records. Repeated evidence is flagged once; later claim or source revisions can create a new finding. Closing a flag does not correct a claim.

The optional model Curator reads context and sources, reviews freeform contradictions and accuracy, and may write evidence-backed suggestions or briefings. It never edits a claim, fills links silently, dispatches work or runs a proposed operation. A person or authenticated author explicitly records any correction as a new revision with the reason/source. Deterministic evidence checks continue regularly without a model key when automatic curation is enabled.

Hermes consumes focused context, works using its own runtime/tools, and explicitly records sourced outcomes or learning. The repo plugin supplies `rs_context` and `rs_learn`. It has no runtime interception hooks, heartbeat, auto-extraction, dispatch or skill installation. Long-term ownership of reusable Hermes skills remains open; do not sync or manage SKILL.md.

Application authentication, company-scoped API identities, role checks, reference validation, append-only revisions, idempotent operation outcomes, immutable attachments and data rollback are retained. Signed-in people are still server owners with access to all companies; API keys are restricted to their own company. Per-person company membership is outside this redesign.

Current Log content credits its last editor; creation time determines event ordering. API readback exposes the original assertion separately, and full revisions preserve each actor and body. Learning writes require a nonblank citation or a current source record across API/CLI/web; existing learning without current evidence remains readable and receives an unsupported finding. Citations do not independently verify claims. Project source inventory deduplicates direct sources and citations on related claims.

The optional model performs an initial accuracy baseline over existing facts/knowledge: a fixed revision high-water mark and persisted cursor, at most 20 claims per review call, through the existing daily spending gate. Successful batches advance the cursor; skipped/failed batches do not. Restart resumes it; later writes use incremental review. Deterministic evidence scanning continues independently. The spending gate is checked before each duty, not a hard mid-conversation dollar limit.
